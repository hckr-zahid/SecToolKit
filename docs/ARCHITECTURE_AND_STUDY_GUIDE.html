sectoolkit: Security Engineering & SOC Automation Architecture Guide

1. Executive Summary & Philosophy

The Security Toolkit (sectoolkit) is a modular, production-grade Python engineering framework built following defensive programming principles from Python Scripting for Cybersecurity Professionals.

Why Python for Security Operations?

Security teams operate in heterogeneous environments where telemetry originates from diverse sources (firewalls, endpoint sensors, network taps, SIEMs, cloud APIs). Python serves as the universal "glue language" of security engineering. However, hastily written scripts often introduce serious vulnerabilities: - Hardcoded credentials and leaked tokens. - Command and SQL injection in automation pipelines. - Memory crashes when reading gigabyte-scale log files. - Alert fatigue due to lack of deduplication and transparent prioritization.

Core Defensive Principles Applied

  1. Validate at the Boundaries: Enforce strict validation (types, ranges, formats) the moment untrusted data enters the application before processing.
  2. Defensive by Default: Reject shell=True, avoid string-concatenated SQL queries, and enforce canonical path containment.
  3. Memory-Conscious Architecture: Utilize Python generators and iterators (yield) to stream data line-by-line rather than reading entire datasets into RAM.
  4. Explainable Prioritization: Provide transparent mathematical formulas for risk scoring instead of opaque "black-box" heuristics.
  5. Auditable Artifacts: Maintain cryptographic integrity (SHA-256) and strict ISO 8601 UTC timestamp normalization.

Module 1: Boundary Validators & Normalization

  • File: validators.py
  • Test Suite: test_validators.py (7 tests)

Why We Need It

Security tools consume untrusted network inputs (command-line flags, HTTP headers, syslog lines). If a script accepts an unvalidated port or username, downstream systems can crash, suffer injection attacks, or yield false positive matches.

Core Functions

  1. parse_port(value: str | int) -> int:
  2. Enforces that network ports are valid integers in range $[1, 65535]$.
  3. Handles type casting gracefully; raises descriptive ValueError on non-numeric strings or out-of-range values.
  4. normalize_username(value: str) -> str:
  5. Trims whitespace and applies casefold().
  6. Why casefold() over lower()? In international character sets (e.g. German ß $\rightarrow$ ss), casefold() handles aggressive caseless matching, eliminating identity spoofing through unicode trickery.
  7. is_private_ip(ip_text: str) -> bool:
  8. Uses the standard library ipaddress module to evaluate IPv4/IPv6 address strings.
  9. Accurately identifies RFC 1918 private ranges, loopback (127.0.0.0/8), and link-local ranges.

Module 2: Path Traversal & Secret Redaction

  • File: security.py
  • Test Suite: test_security.py (5 tests)

Why We Need It

  • Directory Traversal: When analysts supply output paths or filenames, an uncontained path (e.g., ../../etc/shadow) could allow attackers or faulty scripts to overwrite system files.
  • Credential Leakage: Logs and diagnostic outputs frequently contain passwords, bearer tokens, and session cookies. Logging these creates severe compliance violations.

Core Functions

  1. safe_child(root: Path, user_supplied: str) -> Path:
  2. Resolves absolute canonical paths (.resolve()) for both the boundary root and candidate target.
  3. Validates that resolved_root in candidate.parents or candidate == resolved_root.
  4. Prevents directory traversal attacks (../, symlink attacks) with an explicit ValueError.
  5. redact_secrets(data: Any, sensitive_keys: set[str] | None = None) -> Any:
  6. Recursively traverses nested dictionaries, lists, and tuples.
  7. Detects keys such as password, token, authorization, api_key, secret, and cookie.
  8. Replaces values with [REDACTED] while leaving operational metadata intact.

Module 3: Threat Intelligence & IOC Processing

  • File: ioc.py
  • Test Suite: test_ioc.py (4 tests)

Why We Need It

Threat intelligence workflows require extracting indicators of compromise (IOCs) from unstructured reports, defanging them to prevent accidental analyst clicks, and calculating file hashes.

Core Functions

  1. sha256_file(path: Path | str, chunk_size: int = 1MB) -> str:
  2. Reads files in 1 MB chunks to calculate cryptographic digests without loading multi-gigabyte malware samples into RAM.
  3. extract_iocs(text: str) -> dict[str, list[str]]:
  4. Uses regular expressions to extract candidate IPv4 addresses, SHA-256 hashes (64 hex characters), and MD5 hashes (32 hex characters).
  5. Validates IP addresses with ipaddress.IPv4Address to reject invalid octets (e.g. 999.999.999.999).
  6. Normalizes hashes to lowercase and deduplicates into sorted lists.
  7. defang_indicator(indicator: str) -> str:
  8. Neutralizes live URLs and IPs for safe sharing: converts http:// / https:// into hxxp:// / hxxps:// and replaces dots . with [.].

Module 4: SOC Triage & Alert Normalization

  • File: triage.py
  • Test Suite: test_triage.py (8 tests)

Why We Need It

SOC analysts are overwhelmed by alert volume. Different SIEMs use conflicting schemas, and brute-force or port scans generate thousands of redundant events.

Core Functions

  1. normalize_alert(raw: Mapping) -> dict:
  2. Translates vendor-specific fields (@timestamp, time, src_ip, rule_name, signature) into a predictable dictionary schema.
  3. fingerprint(alert: Mapping) -> str:
  4. Generates a deterministic SHA-256 hash using sorted JSON keys:
    • rule: Alert signature or detection logic.
    • host: Target host.
    • src: Attacking source IP.
    • time_bucket: Timestamp truncated to minute precision (YYYY-MM-DDTHH:MM).
  5. Alerts with the same signature, attacker, and target within the same minute share an identical fingerprint.
  6. priority_score(severity, confidence, asset_criticality) -> float:
  7. Computes transparent risk prioritization: $$\text{Score} = (\text{Severity} \times 0.45) + (\text{Confidence} \times 0.30) + (\text{Criticality} \times 0.25)$$
  8. Severity weights: Low=1, Medium=2, High=3, Critical=4. Ratings range from 1.0 to 4.0.
  9. triage_alerts(raw_alerts, ...) -> list[dict]:
  10. Ingests alerts, normalizes fields, aggregates duplicates by fingerprint (incrementing count), computes priority scores, filters below min_priority, and returns alerts sorted descending by urgency.

Module 5: Large Datasets & Log Streaming

  • File: log_stream.py
  • Test Suite: test_log_stream.py (6 tests)

Why We Need It

Enterprise firewall and web proxy logs range from 10 GB to several terabytes. Reading a 5 GB log file with handle.read() or handle.readlines() exhausts server memory and crashes the process.

Core Functions

  1. stream_lines(path, needle=None, encoding="utf-8") -> Iterator[tuple[int, str]]:
  2. Opens files with errors="replace" to handle corrupted byte sequences gracefully.
  3. Yields (line_number, line_content) one line at a time via a Python generator, maintaining an $O(1)$ memory footprint.
  4. stream_json_lines(path) -> Iterator[tuple[int, dict]]:
  5. Streams JSON Lines / NDJSON logs (common in modern SIEM and EDR exports).
  6. Skips malformed lines safely without aborting the pipeline.
  7. batch_stream(items, batch_size=100) -> Iterator[list]:
  8. Chunks streaming items into bounded batches, enabling bulk database insertions or paginated API requests.

Module 6: Network & Web Telemetry

  • File: net_audit.py
  • Test Suite: test_net_audit.py (5 tests)

Why We Need It

Security operations require active verification of authorized endpoints, subnet calculations, and parsing network intrusion detection telemetry (Suricata eve.json / Zeek conn.log).

Core Functions

  1. check_tcp(host: str, port: int, timeout: float = 2.0) -> bool:
  2. Audits TCP service availability with socket timeouts to prevent indefinite hanging.
  3. Validates port numbers using Module 1's parse_port.
  4. subnet_hosts(cidr: str) -> list[str]:
  5. Parses CIDR subnets (e.g. 192.168.1.0/29) using ipaddress.ip_network(strict=False) and extracts all usable host IP addresses.
  6. parse_suricata_eve(path, event_type="alert") -> Iterator[dict]:
  7. Connects to Module 5's stream_json_lines to filter Suricata network events on the fly.
  8. summarize_top_talkers(events, key="src_ip", limit=10) -> list[tuple[str, int]]:
  9. Aggregates event volume by key (source IP, destination port, username) using collections.Counter to surface anomalies and brute-force sources.

Module 7: Digital Forensics & Safe Execution

  • File: forensics.py
  • Test Suite: test_forensics.py (5 tests)

Why We Need It

Forensic integrity demands defensible evidence collection. Evidence must be hashed deterministically, timestamps must be unambiguous, and external tools must be invoked without command injection vulnerabilities.

Core Functions

  1. generate_manifest(directory: Path | str) -> list[dict]:
  2. Recursively traverses an evidence directory in deterministic alphabetical order.
  3. Generates an immutable manifest capturing relative path, file size in bytes, SHA-256 digest, and collection timestamp in UTC.
  4. verify_manifest(manifest, directory) -> dict[str, list[str]]:
  5. Compares current files against the original manifest.
  6. Categorizes findings into matched (intact), modified (tampered/corrupted), and missing (deleted).
  7. parse_iso_timestamp(value: str) -> datetime:
  8. Parses ISO 8601 strings and normalizes them to UTC.
  9. Rejects timezone-naive timestamps to prevent correlation errors across disparate sensor clocks.
  10. safe_exec(cmd_args: list[str], timeout: float = 10.0) -> tuple[int, str, str]:
  11. Executes external system utilities (e.g., tshark, nmap) safely using subprocess.run(shell=False) with a list of arguments.
  12. Prevents command injection attacks (e.g. ; rm -rf / or $(whoami)).

Module 8: Parameterized SQLite & Concurrency

  • File: storage.py
  • Test Suite: test_storage.py (4 tests)

Why We Need It

Security scripts often require persistent local evidence storage and high-throughput network tasks. String concatenation in SQL statements leads directly to SQL Injection (SQLi), while unconstrained concurrency can trigger denial-of-service on target services.

Core Components

  1. EvidenceStore Class:
  2. Encapsulates a local SQLite database with sqlite3.Row factory for named column access.
  3. Strict Parameterization: Queries use ? placeholders (e.g. VALUES (?, ?, ?, ?)), eliminating SQL injection risks.
  4. Supports context management (with EvidenceStore("triage.db") as store:).
  5. Enforces unique fingerprint constraints on alerts to prevent duplicate database entries.
  6. bounded_worker_pool(func, items, max_workers=4) -> list[tuple]:
  7. Uses concurrent.futures.ThreadPoolExecutor to execute I/O-bound tasks concurrently.
  8. Bounds concurrency to prevent thread exhaustion.
  9. Captures per-worker exceptions gracefully without crashing the overall workflow.

Module 9: Central CLI & Packaging

  • File: cli.py & pyproject.toml
  • Test Suite: test_cli.py (3 tests)

Why We Need It

Security analysts need an ergonomic, scriptable terminal interface that integrates all toolkit capabilities into a single binary (sectoolkit).

CLI Commands

  • sectoolkit triage <alerts.json> [--min-score 2.0]: Ingests, normalizes, deduplicates, and ranks raw alert batches.
  • sectoolkit manifest <evidence_dir> [-o output.json]: Generates a cryptographic evidence manifest.
  • sectoolkit ioc "<text_or_file>": Parses unstructured threat intel and extracts validated IOCs.
  • sectoolkit audit-port <host> <port> [--timeout 2.0]: Checks target port accessibility.

Packaging Configuration

Standardized pyproject.toml configuration enables zero-dependency installation and global CLI registration via pip:

.venv/bin/pip install --no-build-isolation -e .

5. How It Works in Future Operational Deployments

sequenceDiagram
    autonumber
    participant Sensor as SIEM / Sensor / EDR
    participant Pipeline as sectoolkit Pipeline
    participant DB as Evidence Store (SQLite/PostgreSQL)
    participant Analyst as Analyst Queue / SOAR

    Sensor->>Pipeline: Raw JSON Events Stream
    Pipeline->>Pipeline: stream_json_lines() + normalize_alert()
    Pipeline->>Pipeline: fingerprint() Deduplication
    Pipeline->>Pipeline: priority_score() Risk Calculation
    Pipeline->>DB: add_alert() [Parameterized Insert]
    Pipeline->>Analyst: Ranked Alerts (score >= threshold)
    Analyst->>Pipeline: Request Forensic Artifacts / Manifest
    Pipeline->>DB: Query Evidence & IOCs

Operational Use Cases

  1. Automated SOC Ingestion & Triage:
  2. Schedule sectoolkit triage via cron or SOAR to ingest hourly alert dumps from Splunk, Elastic, or Microsoft Sentinel.
  3. Filter out duplicate noise and route critical alerts ($\ge 3.0$) straight to high-priority analyst queues.
  4. DFIR Evidence Ingestion & Chain of Custody:
  5. Run sectoolkit manifest /mnt/evidence/drive_image -o manifest.json immediately upon receiving forensic images.
  6. Run sectoolkit verify_manifest prior to courtroom testimony or post-incident review to prove data was not altered.
  7. Threat Intel Ingestion Pipeline:
  8. Pipe raw OSINT blogs or CISA advisories into sectoolkit ioc to extract indicators, store them in EvidenceStore, and defang them for safe analyst review.
  9. Active Perimeter & Internal Audits:
  10. Combine subnet_hosts with bounded_worker_pool(check_tcp, hosts) to conduct non-intrusive, authorized port reachability checks across enterprise subnets.
